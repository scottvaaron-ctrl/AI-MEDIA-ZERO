# Sound (Kokoro voice, -14 LUFS) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** New videos are narrated by Kokoro's Bella (`kokoro:af_bella`) with a whole-video fallback to Piper, and every
final video is levelled to -14 LUFS (±1 LU), true peak ≤ -1 dBTP.

**Architecture:** A `KokoroTTSProvider` beside Piper; a `VoiceRouterTTS` that sends `kokoro:*` voices to Kokoro and
everything else to Piper and turns any Kokoro failure into `VoiceUnavailable`; the producer catches that and
re-assembles the whole video with `en_US-kristin-medium`. The owner fixes the channel voice with `aimz voice set`.
The renderer's final pass always runs an audio filter chain ending in a two-pass `loudnorm`, then measures the output.

**Tech Stack:** Python 3.14, `kokoro-onnx` (optional extra `voice`), numpy, ffmpeg `loudnorm`, typer, pytest with
`httpx.MockTransport`.

**Spec:** `docs/superpowers/specs/2026-10-09-sound-design.md`

## Global Constraints

- $0: no paid service; model files come from the public kokoro-onnx GitHub release `model-files-v1.0`.
- Cleared Kokoro voices: `kokoro:af_bella` only. Any other `kokoro:` id raises `ProviderUnavailable`.
- Fallback voice: `en_US-kristin-medium`. One video never mixes voices.
- Model files: `kokoro-v1.0.int8.onnx`, `voices-v1.0.bin` in `KOKORO_MODEL_DIR` (default `<data_dir>/models/kokoro`),
  `KOKORO_AUTO_DOWNLOAD` default true; download to `<name>.part`, then rename.
- Tests never download or load the real model (autouse conftest guard).
- Kokoro output: 16-bit mono WAV at the model's rate (24 kHz). Speed = `1 / length_scale`, clamped to 0.5–2.0. Lang
  `en-us` for ids starting `a`, `en-gb` for `b`.
- Loudness target string: `loudnorm=I=-14:TP=-1:LRA=11`; second pass adds `measured_I/TP/LRA/thresh`, `offset`,
  `linear=true`; then `-ar 48000`; AAC 128k unchanged.
- Out-of-range loudness (outside -14 ±1 LU, or peak > -1 dBTP) is a logged warning, never a failure.
- Guideline lock of `voice` still outranks the identity.
- Code style: ruff + mypy clean; match surrounding comment density.

## Review Focus

1. **AAC re-encode raises the true peak** above the loudnorm target (often +0.2–0.6 dB), so the output can read
   > -1 dBTP although loudnorm aimed at -1. Task 5's tone test pins ≤ -1.0 on the encoded file; if it fails, lower
   only the loudnorm `TP` target (e.g. -1.5) and note why in a comment — the requirement on the output stays.
2. **Kill switch or budget refusal inside Kokoro** must not be turned into `VoiceUnavailable` (that would silently
   narrate with Piper while the kill switch is on). Task 2 tests that `KillSwitchEngaged` and `BudgetDenied` pass
   through the router unchanged.
3. **Kokoro fails mid-video** (beat 3 of 6), not on beat 0: the retry must rebuild every scene with the fallback voice.
   Task 3 tests a fake that fails on the third call and asserts every scene WAV came from the fallback.
4. **Owner voice taken by another channel**: `aimz voice set` must refuse a voice another instance holds (same rule
   as `propose`). Task 4 tests it.
5. **Silent or near-silent narration** (silent TTS in tests, a loop tail): loudnorm's measured `input_i` is `-inf`;
   pass 2 must not be fed `-inf`. Task 5 tests `parse_loudnorm_json` on a `-inf` block returning None (→ single pass).

**Interfaces:**
- Produces (module level in `ffmpeg_renderer.py`):
  - `LOUDNORM = "loudnorm=I=-14:TP=-1:LRA=11"`
  - `parse_loudnorm_json(stderr: str) -> dict[str, float] | None` — last `{...}` block with `input_i`, `input_tp`,
    `input_lra`, `input_thresh`, `target_offset` as floats; None if absent, unparsable, or any value not finite.
  - `loudnorm_second_pass(m: dict[str, float]) -> str` → `LOUDNORM + ":measured_I=..:measured_TP=..:measured_LRA=..:measured_thresh=..:offset=..:linear=true"`
  - `FFmpegRenderer._audio_mix(timeline, work, ass_filter: str | None, tail: str) -> tuple[list[str], list[str]]` —
    always `-filter_complex`; audio ends `{audio}{tail}[afinal]`; `ass_filter=None` builds the audio-only graph (no
    `[v]`, maps only `[afinal]`) for measuring.
  - `FFmpegRenderer.measure_loudness(path: Path) -> tuple[float, float] | None` → `(input_i, input_tp)` of a file.
  - A `_run_capture(args, cwd, label) -> str` sibling of `_run` with `-loglevel info` returning stderr.

Final pass: pass 1 = concat + mix inputs + audio-only graph with `LOUDNORM + ":print_format=json"`, `-vn -f null -`;
pass 2 = the real command with `tail = loudnorm_second_pass(m)` and `-ar 48000`. If pass 1 raises or parses to None,
log `"loudness pass 1 failed; single-pass loudnorm"` and use `tail = LOUDNORM`. After the render, `measure_loudness`
the output into the `RenderResult`; outside -14 ±1 or peak > -1 → `log.warning`. Producer adds
`run.note("loudness", {**existing, video_id: {"loudness_lufs": .., "true_peak_dbtp": ..}})`.
